# Journal des offres consultées — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tenir, par titulaire, un journal daté des offres lues puis écartées (motif Profil / Poste / Distance), visible en lecture seule par France Travail et alimentable par l'API Claude.

**Architecture:** Nouvelle table `offre_consultee` (Liquibase 010) + entité, repository filtré par titulaire, service, page Thymeleaf `/consultees` (formulaire + liste paginée, PRG) et endpoint `POST /api/offres-consultees` dans la chaîne API existante. Aucun changement de sécurité ni de `.env`.

**Tech Stack:** Spring Boot 4.0.2, Java 17, Spring Data JPA, Liquibase, Thymeleaf + thymeleaf-extras-springsecurity, Lombok, JUnit 5 + Mockito + AssertJ.

**Spec:** `docs/superpowers/specs/2026-11-18-offres-consultees-design.md`

## Global Constraints

- Code, noms, UI et Javadoc en **français** (style maison `javadoc-fr`).
- Toute requête sur `offre_consultee` filtrée par titulaire ; jamais `findById/findAll/count/deleteById` hérités (seul `save`). Un id de l'autre titulaire = id inconnu → `NoSuchElementException` → 404.
- Le titulaire vient toujours de `UtilisateurCourant.titulaire()`, jamais d'un paramètre de requête.
- Schéma via Liquibase uniquement (`ddl-auto: validate`).
- Motif = codes de `MotifEcart` : 1 = Profil, 2 = Poste, 3 = Distance (pas de « Autre »).
- Pagination : `@Value("${gestojob.max-annonces-par-page:7}")` (pas de nouvelle variable `.env`).
- Chaque méthode publique a ses tests (repère JaCoCo 80 %, non bloquant).
- Commits FR (Conventional Commits, skill `git-commit`), sur la branche `feat/offres-consultees`, jamais sur `master`, sans push.

## Review Focus

1. **Lien `javascript:`** (page ou API) : rendu dans un `href`, ce serait une XSS. Attendu : seuls les liens `http://` ou `https://` sont acceptés (validation `@Pattern`), sinon erreur de saisie / 400. → tests Task 2 et Task 5.
2. **Champs trop longs** (intitulé collé depuis une offre avec description) : attendu un message de validation, pas une 500 SQL. → `@Size` dans form et DTO, tests Task 2 et Task 5.
3. **Suppression d'une entrée de l'autre titulaire** (id deviné) : attendu 404, rien supprimé. → test Task 3.
4. **Lecteur France Travail** : voit la page mais ni formulaire ni bouton supprimer, et un POST lui est refusé (403, règle existante). → test Task 4 sur `SecurityConfig` si `SecurityConfigTest` couvre les POST, sinon vérification manuelle Task 6.
5. **Motif hors liste** (code 0, 4, null ou nom inconnu par l'API) : attendu erreur de validation / 400 JSON, pas une 500. → tests Task 1 et Task 5.
